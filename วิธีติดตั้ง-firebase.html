1สร้างโปรเจกต์ Firebase

  1. เปิด console.firebase.google.com แล้วลงชื่อเข้าใช้ด้วยบัญชี Google
  2. กด Create a project (หรือ Add project ถ้ามีโปรเจกต์อยู่แล้ว)
  3. ตั้งชื่อโปรเจกต์ว่า psu-lasc-medicine → กด Continue
    Firebase จะเติมตัวเลขต่อท้ายให้อัตโนมัติถ้าชื่อซ้ำกับคนอื่นทั่วโลก เช่น psu-lasc-medicine-a1b2c — ไม่เป็นไร ใช้ได้ปกติ แต่ให้จำชื่อจริงนี้ไว้
  4. หน้า Google Analytics → ปิดสวิตช์ (ระบบนี้ไม่ได้ใช้) → กด Create project
  5. รอประมาณ 30 วินาที → กด Continue

2เปิดใช้งาน Authentication

ส่วนนี้คือระบบล็อกอินของสัตวแพทย์

  1. เมนูด้านซ้าย หา Authentication (อาจอยู่ใต้หัวข้อ Build หรือ Project shortcuts แล้วแต่เวอร์ชันของหน้าจอ)
  2. กด Get started
  3. แท็บ Sign-in method → ในรายการ Native providers กด Email/Password
  4. เปิดสวิตช์ตัวแรก Enable ให้เป็นสีฟ้า
    สวิตช์ตัวที่สอง Email link (passwordless sign-in) ไม่ต้องเปิด — ระบบนี้ใช้รหัสผ่านอย่างเดียว
  5. กด Save

3สร้าง Realtime Database

⚠ ระวังสับสน — Firebase มีฐานข้อมูล 2 แบบ ต้องเลือก Realtime Database เท่านั้น
ห้ามเลือก Cloud Firestore เพราะระบบนี้เขียนขึ้นสำหรับ Realtime Database ถ้าเลือกผิดจะใช้งานไม่ได้เลย
  1. เมนูด้านซ้าย หา Realtime Database (อยู่ใต้หัวข้อ Build หรือ Databases & Storage)
  2. กด Create Database
  3. Realtime Database location → เลือก Singapore (asia-southeast1)
    เลือกสิงคโปร์เพราะใกล้ไทยที่สุด ทำให้ระบบตอบสนองเร็ว เลือกแล้วเปลี่ยนไม่ได้ ต้องสร้างฐานข้อมูลใหม่
  4. กด Next
  5. Security rules → เลือก Start in locked mode (ล็อกไว้ก่อน เดี๋ยวใส่กฎจริงในขั้นที่ 4)
  6. กด Enable
✅ เสร็จแล้วจะเห็นแถบที่อยู่ฐานข้อมูลด้านบนตาราง หน้าตาประมาณ
https://psu-lasc-medicine-default-rtdb.asia-southeast1.firebasedatabase.app
คัดลอกเก็บไว้ จะได้ใช้ในขั้นที่ 6

4วางกฎความปลอดภัย

กฎนี้กำหนดว่าใครอ่านหรือเขียนอะไรได้บ้าง — เป็นสิ่งเดียวที่ปกป้องข้อมูลจริง ๆ

  1. ในหน้า Realtime Database กดแท็บ Rules
  2. ลบข้อความเดิมทั้งหมด แล้ววางโค้ดด้านล่างนี้แทน (เหมือนกับไฟล์ firebase-rules.json ในโฟลเดอร์ระบบ)
  3. กด Publish
{
  "rules": {
    ".read": false,
    ".write": false,

    "allowed": {
      ".read": "auth != null",
      ".write": false
    },

    "data": {
      ".read":  "auth != null && root.child('allowed').child(auth.uid).exists()",
      ".write": "auth != null && root.child('allowed').child(auth.uid).exists()",

      "medicine": {

        "public": {
          ".read": true
        },

        "inbox": {
          "$ref": {
            ".write": "!data.exists()",
            ".validate": "$ref.matches(/^REQ-[0-9]{8}-[A-Z0-9]{4}$/) && newData.hasChildren(['ref','name','org','license','phone','email','startUse','items','createdAt']) && newData.child('name').isString() && newData.child('name').val().length > 0 && newData.child('name').val().length <= 120 && newData.child('org').isString() && newData.child('org').val().length <= 200 && newData.child('license').isString() && newData.child('license').val().length <= 100 && newData.child('phone').isString() && newData.child('phone').val().length <= 40 && newData.child('email').isString() && newData.child('email').val().matches(/^[^@\\s]+@[^@\\s]+\\.[^@\\s]+$/) && newData.child('email').val().length <= 120 && (!newData.hasChild('note') || newData.child('note').val().length <= 2000) && (!newData.hasChild('studyTitle') || newData.child('studyTitle').val().length <= 300) && (!newData.hasChild('addr') || newData.child('addr').val().length <= 300)"
          }
        }

      }
    }
  }
}
กฎนี้ทำอะไร
เส้นทางอ่านเขียน
data/**เฉพาะผู้ที่มี UID ใน allowedเฉพาะผู้ที่มี UID ใน allowed
data/medicine/publicทุกคน (มีแค่จำนวนวันตาม SOP กับรายชื่อยา ไม่มีราคาและข้อมูลส่วนบุคคล)เฉพาะผู้มีสิทธิ์
data/medicine/inbox/{REQ-…}อ่านไม่ได้จากภายนอกสร้างใหม่ได้ แต่ทับหรือลบของเดิมไม่ได้
นักวิจัยที่มีลิงก์แบบฟอร์มส่งคำขอได้โดยไม่ต้องล็อกอิน ซึ่งเป็นเจตนาของการออกแบบ กฎจึงจำกัดไว้ว่า สร้างได้อย่างเดียว ตรวจรูปแบบรหัส ตรวจฟิลด์บังคับ และจำกัดความยาวทุกช่อง และคำขอทุกรายการไม่เข้าทะเบียนจนกว่าสัตวแพทย์จะกด “รับเข้าระบบ”

5ลงทะเบียนเว็บแอปและคัดลอกค่าเชื่อมต่อ

  1. กดไอคอน ⚙️ เฟือง ข้างคำว่า Project Overview → เลือก Project settings
  2. แท็บ General เลื่อนลงล่างสุดหาหัวข้อ Your apps
  3. กดไอคอน </> (Web)
  4. App nickname ใส่ psu-lasc-medicine
    ไม่ต้องติ๊ก “Also set up Firebase Hosting” — เราใช้ GitHub Pages อยู่แล้ว
  5. กด Register app
  6. จะเห็นโค้ดชุดหนึ่ง คัดลอกเฉพาะส่วนในวงเล็บปีกกาของ firebaseConfig เก็บไว้
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "psu-lasc-medicine.firebaseapp.com",
  databaseURL: "https://psu-lasc-medicine-default-rtdb.asia-southeast1.firebasedatabase.app",
  projectId: "psu-lasc-medicine",
  storageBucket: "psu-lasc-medicine.firebasestorage.app",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abcdef1234567890"
};
⚠ ถ้าไม่เห็นบรรทัด databaseURL ให้ใช้ที่อยู่ที่คัดลอกไว้จากขั้นที่ 3 มาเติมเอง ขาดบรรทัดนี้ไม่ได้เด็ดขาด เพราะระบบใช้ Realtime Database เป็นหลัก
ค่าชุดนี้ไม่ใช่ความลับ — Firebase ออกแบบให้ฝังในหน้าเว็บได้โดยตรง ใครเปิดดูโค้ดหน้าเว็บก็เห็น สิ่งที่ปกป้องข้อมูลคือกฎในขั้นที่ 4 ไม่ใช่การซ่อนค่าเหล่านี้

6แก้ไฟล์ firebase-config.js

เปิดไฟล์ firebase-config.js ในโฟลเดอร์ lasc-medicine ด้วย Notepad หรือโปรแกรมแก้ข้อความใดก็ได้

หาส่วนนี้ แล้ววางค่าที่คัดลอกจากขั้นที่ 5 ทับลงไป

window.FIREBASE_CONFIG = {
  apiKey: "วางค่าใหม่",
  authDomain: "วางค่าใหม่",
  databaseURL: "วางค่าใหม่",
  projectId: "วางค่าใหม่",
  storageBucket: "วางค่าใหม่",
  messagingSenderId: "วางค่าใหม่",
  appId: "วางค่าใหม่"
};
ข้อควรระวังตอนแก้
  • เครื่องหมาย " ครอบค่าทุกบรรทัด และ , ท้ายบรรทัด ต้องอยู่ครบ
  • บรรทัดสุดท้าย appId ไม่มี เครื่องหมาย ,
  • บันทึกเป็น UTF-8 (Notepad: Save as → Encoding เลือก UTF-8)
  • ไม่ต้องแก้ window.MEDICINE_ROOT และ window.MEDICINE_APP_URL ด้านล่าง
✅ ไฟล์นี้เป็นไฟล์เดียวที่ต้องแก้ — ทั้งระบบหลักและแบบฟอร์มนักวิจัยอ่านค่าจากที่นี่ร่วมกัน

7เพิ่มโดเมนที่อนุญาต

⚠ ขั้นนี้คนพลาดบ่อยที่สุด — ถ้าข้ามไป จะกดเข้าสู่ระบบแล้วไม่มีอะไรเกิดขึ้น หรือขึ้น error แปลก ๆ
  1. กลับไปที่ Authentication
  2. แท็บ Settings → เมนูย่อย Authorized domains
  3. กด Add domain
  4. ใส่ kwanchanokd.github.io → กด Add
ในรายการจะมี localhost และ psu-lasc-medicine.firebaseapp.com อยู่แล้ว ปล่อยไว้ได้

8สร้างบัญชีผู้ใช้

  1. ที่ Authentication → แท็บ Users
  2. กด Add user
  3. ใส่อีเมลของสัตวแพทย์ เช่น kwanchanok.d@psu.ac.th
  4. ตั้งรหัสผ่าน อย่างน้อย 6 ตัวอักษร (จดเก็บไว้ให้ดี)
  5. กด Add user
  6. ในรายการจะมีคอลัมน์ User UID เป็นตัวอักษรยาว ๆ เช่น kJ8xP2mNq... กดคัดลอกเก็บไว้ จะใช้ในขั้นที่ 9
✅ บัญชีนี้แยกขาดจากระบบใบเสนอราคา ตั้งรหัสผ่านใหม่ได้ตามใจ ไม่กระทบระบบอื่น
ผู้ใช้สมัครเองไม่ได้ — ระบบออกแบบให้ผู้ดูแลเป็นคนสร้างบัญชีให้เท่านั้น เป็นการป้องกันคนนอกเข้าถึงข้อมูลคำขอและราคายา

9ให้สิทธิ์เข้าถึงข้อมูล

⚠ ข้ามขั้นนี้ไม่ได้ — ถ้าไม่ทำ จะเข้าสู่ระบบได้ แต่ขึ้นข้อความว่า “บัญชีนี้ยังไม่ได้รับสิทธิ์เข้าถึงข้อมูล” และไม่เห็นข้อมูลอะไรเลย
  1. ไปที่ Realtime Database → แท็บ Data
  2. ชี้เมาส์ที่บรรทัดบนสุด (ที่อยู่ฐานข้อมูล) แล้วกดเครื่องหมาย + สีเขียว
  3. ช่อง Name ใส่ allowed → ช่อง Value เว้นว่างไว้
  4. กด + อีกครั้งที่บรรทัดถัดเข้าไป (ใต้ allowed)
  5. ช่อง Name วาง User UID ที่คัดลอกจากขั้นที่ 8
    ช่อง Value ใส่ true
  6. กด Add

ผลลัพธ์ที่ถูกต้องจะมีหน้าตาแบบนี้

psu-lasc-medicine-default-rtdb
└── allowed
    └── kJ8xP2mNq4RtY7wZ...: true
เพิ่มคนอื่นภายหลัง — ทำซ้ำขั้นที่ 8 เพื่อสร้างบัญชี แล้วกลับมาเพิ่ม UID ของคนนั้นใต้ allowed อีกบรรทัด ไม่ต้องแก้โค้ดหรือกฎใด ๆ

10อัปโหลดและทดสอบ

อัปโหลดไฟล์ที่แก้แล้ว

  1. เปิด github.com/kwanchanokd/psu-lasc-medicine
  2. กด Add file → Upload files
  3. ลากไฟล์ firebase-config.js ที่แก้แล้วลงไป
  4. กด Commit changes แล้วรอ 1–2 นาทีให้ GitHub Pages สร้างเว็บใหม่

ทดสอบฝั่งสัตวแพทย์

  1. เปิด https://kwanchanokd.github.io/psu-lasc-medicine/
    ถ้ายังเห็นของเก่า กด Ctrl + Shift + R เพื่อโหลดใหม่แบบข้ามแคช
  2. กด 🔑 เข้าสู่ระบบ ใส่อีเมลและรหัสผ่านจากขั้นที่ 8
  3. ป้ายมุมขวาบนต้องเปลี่ยนเป็น ☁ ซิงก์แล้ว · อีเมลของท่าน

ทดสอบฝั่งนักวิจัย

  1. เปิด https://kwanchanokd.github.io/psu-lasc-medicine/request.html
  2. กรอกข้อมูลทดสอบให้ครบ → กด 📨 ส่งคำขอ
  3. ต้องได้รหัสอ้างอิงหน้าตา REQ-25691002-XXXX
  4. กลับไปที่ระบบหลัก แท็บ 📥 คำขอเข้าใหม่ → ต้องเห็นคำขอที่เพิ่งส่ง
  5. ทดสอบเสร็จกด ✖ ตีกลับ / ลบ ทิ้ง
✅ ถ้าผ่านครบทุกข้อ = ติดตั้งสมบูรณ์ ระบบพร้อมใช้งานจริง

🔧 แก้ปัญหาที่พบบ่อย

อาการสาเหตุและวิธีแก้
ป้ายขึ้น ⚠ ไม่พบการตั้งค่า Firebase ยังไม่ได้อัปโหลด firebase-config.js ขึ้น GitHub หรือไฟล์มีวงเล็บ/เครื่องหมายคำพูดไม่ครบ — เปิดไฟล์ตรวจอีกครั้งตามข้อควรระวังในขั้นที่ 6
กดเข้าสู่ระบบแล้วไม่มีอะไรเกิดขึ้น ยังไม่ได้ทำขั้นที่ 7 — เพิ่ม kwanchanokd.github.io ใน Authorized domains
อีเมลหรือรหัสผ่านไม่ถูกต้อง ตรวจที่ Authentication → Users ว่ามีอีเมลนี้จริงและสะกดตรงกัน ถ้าจำรหัสไม่ได้ กด ⋮ ท้ายแถว → Reset password
บัญชีนี้ยังไม่ได้รับสิทธิ์เข้าถึงข้อมูล ยังไม่ได้ทำขั้นที่ 9 หรือ UID ที่ใส่ไม่ตรง — คัดลอก UID จากหน้า Users มาใหม่ ระวังช่องว่างติดมาด้วย
ฟอร์มนักวิจัยขึ้น ส่งคำขอไม่สำเร็จ ยังไม่ได้กด Publish กฎในขั้นที่ 4 หรือวางกฎผิดตำแหน่ง — เปิดแท็บ Rules ดูว่าไม่มีจุดแดงแสดงข้อผิดพลาด
ช่องชื่อยาในฟอร์มไม่มีรายการแนะนำ ยังไม่เคยเข้าสู่ระบบในระบบหลักหลังติดตั้ง — ล็อกอิน 1 ครั้ง ระบบจะส่งรายชื่อยาขึ้นคลาวด์ให้เอง
ฐานข้อมูลสร้างผิดเป็น Firestore กลับไปสร้าง Realtime Database ใหม่ตามขั้นที่ 3 — Firestore ที่สร้างไว้ปล่อยทิ้งได้ ไม่เสียค่าใช้จ่าย
