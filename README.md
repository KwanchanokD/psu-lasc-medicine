# ระบบบริการยาและเวชภัณฑ์เพื่องานวิจัย — PSU:LASC

ระบบรับคำขอซื้อยาและเวชภัณฑ์เพื่อใช้ในงานวิจัย ของ **ศูนย์บริการสัตว์ทดลอง มหาวิทยาลัยสงขลานครินทร์**
(Laboratory Animals Service Center, Prince of Songkla University)

สร้างตามมาตรฐานขั้นตอนการปฏิบัติงาน **SOP รหัส MED101 — ข้อปฏิบัติในการขอซื้อยาและเวชภัณฑ์เพื่อใช้ในงานวิจัย**

🔗 **เปิดใช้งาน:** https://kwanchanokd.github.io/psu-lasc-medicine/

## การตั้งค่า Firebase

ค่าเชื่อมต่อทั้งหมดอยู่ใน **[`firebase-config.js`](firebase-config.js) ไฟล์เดียว** ซึ่งทั้ง `index.html`
และ `request.html` อ่านร่วมกัน — เปลี่ยนโปรเจกต์ Firebase ได้โดยแก้ไฟล์นั้นที่เดียว ไม่ต้องแตะไฟล์อื่น

### แยกเป็นโปรเจกต์ของระบบยาโดยเฉพาะ

> 📘 **คู่มือฉบับเต็มพร้อมภาพประกอบขั้นตอน ตารางแก้ปัญหา และรายการตรวจสอบ:**
> เปิดไฟล์ [`วิธีติดตั้ง-firebase.html`](วิธีติดตั้ง-firebase.html) ด้วยเบราว์เซอร์
> ตารางด้านล่างเป็นฉบับย่อสำหรับผู้ที่คุ้นเคยกับ Firebase อยู่แล้ว

✅ **ดำเนินการแล้ว** — ระบบใช้โปรเจกต์ `psu-lasc-medicine` ของตัวเอง
บัญชีผู้ใช้ กฎความปลอดภัย และข้อมูล แยกขาดจากระบบใบเสนอราคาและระบบตรวจติดตามสัตว์ฯ

ขั้นตอนด้านล่างเก็บไว้อ้างอิง หากต้องตั้งค่าใหม่หรือย้ายโปรเจกต์ในอนาคต

| ขั้น | ทำที่ | รายละเอียด |
|---|---|---|
| 1 | console.firebase.google.com | **Add project** ตั้งชื่อ `psu-lasc-medicine` (ปิด Google Analytics ได้) |
| 2 | Build → Authentication | **Get started** → Sign-in method → เปิด **Email/Password** |
| 3 | Build → Realtime Database | **Create Database** → เลือก **Singapore (asia-southeast1)** → **Start in locked mode** |
| 4 | Realtime Database → Rules | วางเนื้อหาจาก [`firebase-rules.json`](firebase-rules.json) → **Publish** |
| 5 | Project settings → Your apps | กดไอคอน **`</>`** ตั้งชื่อแอป → **Register app** → คัดลอก `firebaseConfig` |
| 6 | `firebase-config.js` | วางค่าที่คัดลอกทับของเดิม **รวม `databaseURL`** (หาได้จากหน้า Realtime Database) |
| 7 | Authentication → Settings → Authorized domains | **Add domain** → `kwanchanokd.github.io` |
| 8 | Authentication → Users | **Add user** ใส่อีเมล + รหัสผ่านของสัตวแพทย์ → คัดลอก **User UID** |
| 9 | Realtime Database → Data | สร้างลูกชื่อ `allowed` → ใต้นั้นสร้างลูกชื่อเป็น **UID** ค่าเป็น `true` |
| 10 | GitHub | อัปโหลด `firebase-config.js` ทับไฟล์เดิม |

> **ขั้นที่ 7 สำคัญ** — ถ้าไม่เพิ่ม `kwanchanokd.github.io` ใน Authorized domains จะเข้าสู่ระบบไม่ได้
> **ขั้นที่ 9 สำคัญ** — ถ้าไม่มี UID ใน `allowed` จะเข้าสู่ระบบได้แต่ขึ้นว่าไม่มีสิทธิ์เข้าถึงข้อมูล

หลังแยกแล้ว **บัญชีผู้ใช้จะไม่ใช่ชุดเดียวกับระบบใบเสนอราคาอีกต่อไป** ต้องสร้างบัญชีใหม่ในโปรเจกต์นี้
และข้อมูลเดิม (ถ้ามี) ไม่ย้ายตามไปเอง — ให้ใช้ปุ่ม **สำรองข้อมูล / กู้คืนข้อมูล** ในหน้าตั้งค่าระบบย้ายแทน

### โครงสร้างข้อมูล

```
data/medicine/
  ├── requests/{id}      คำขอซื้อยาแต่ละรายการ (เฉพาะผู้มีสิทธิ์)
  ├── master             การตั้งค่าตาม SOP + บัญชียาและราคา (เฉพาะผู้มีสิทธิ์)
  ├── counters/all       เลขรันคำขอ (จองแบบ transaction ไม่ให้ซ้ำข้ามเครื่อง)
  ├── inbox/{REQ-…}      คำขอที่นักวิจัยกรอกเอง — สร้างได้จากภายนอก แก้/อ่านไม่ได้
  ├── processed/{REQ-…}  คำขอที่สัตวแพทย์ตรวจสอบแล้ว (รับเข้าระบบ / ตีกลับ)
  ├── public/config      พารามิเตอร์ SOP + รายชื่อยา สำหรับแบบฟอร์มสาธารณะ (อ่านได้ทุกคน)
  └── updatedAt          เวลาที่แก้ไขล่าสุด
```

### กฎความปลอดภัย

ตั้งแต่มีแบบฟอร์มสาธารณะ (`request.html`) **ต้องอัปเดตกฎความปลอดภัย** — ใช้ไฟล์
[`firebase-rules.json`](firebase-rules.json) วางทับใน Firebase Console → Realtime Database → Rules → Publish

กฎนี้ออกแบบให้:

| เส้นทาง | อ่าน | เขียน |
|---|---|---|
| `data/**` (ทั้งหมด) | เฉพาะ UID ที่อยู่ใน `allowed` | เฉพาะ UID ที่อยู่ใน `allowed` |
| `data/medicine/public` | **ทุกคน** (มีแต่จำนวนวันตาม SOP และรายชื่อยา ไม่มีราคาและข้อมูลส่วนบุคคล) | เฉพาะผู้มีสิทธิ์ |
| `data/medicine/inbox/{REQ-…}` | **อ่านไม่ได้จากภายนอก** | **สร้างใหม่ได้จากภายนอก** แต่ทับของเดิมไม่ได้ (`!data.exists()`) |

การเขียนเข้า `inbox` ถูกจำกัดด้วย: รูปแบบคีย์ต้องเป็น `REQ-YYYYMMDD-XXXX` · ต้องมีฟิลด์บังคับครบ ·
รูปแบบอีเมลต้องถูกต้อง · จำกัดความยาวทุกช่อง · และ**สร้างได้อย่างเดียว แก้หรือลบของเดิมไม่ได้**

> ⚠️ ผู้ที่มีลิงก์แบบฟอร์มสามารถส่งคำขอเข้ามาได้โดยไม่ต้องล็อกอิน ซึ่งเป็นเจตนาของการออกแบบ
> แต่แลกมาด้วยความเสี่ยงที่จะมีคำขอขยะ — คำขอทุกรายการ**ไม่เข้าทะเบียนจนกว่าสัตวแพทย์จะกด “รับเข้าระบบ”**
> และสัตวแพทย์ลบคำขอที่ไม่ต้องการได้ตลอดเวลา

ผู้ใช้ใหม่ (ฝั่งสัตวแพทย์) ต้องให้ผู้ดูแลระบบสร้างบัญชีใน Firebase Authentication และเพิ่ม UID ไว้ใต้ `allowed` (สมัครเองไม่ได้)

## แบบฟอร์มสำหรับนักวิจัย

`request.html` เป็นหน้าแยกที่ **ไม่ต้องเข้าสู่ระบบ** สำหรับให้นักวิจัยกรอกคำขอเอง

🔗 https://kwanchanokd.github.io/psu-lasc-medicine/request.html

```
นักวิจัยกรอกฟอร์ม → data/medicine/inbox → แท็บ “คำขอเข้าใหม่” ของสัตวแพทย์
                                                    ↓
                                    ตรวจสอบ → “รับเข้าระบบ” → ออกเลขที่ → เดินตาม SOP ต่อ
```

- ผู้ยื่นได้ **รหัสอ้างอิง** `REQ-YYYYMMDD-XXXX` และพิมพ์สำเนาคำขอเก็บไว้ได้
- เตือนอัตโนมัติเมื่อยื่นล่วงหน้าน้อยกว่าที่ SOP 6.1 กำหนด
- ช่องชื่อยามีรายการแนะนำจากบัญชียาของหน่วยงาน (ดึงจาก `public/config`)
- ฝั่งสัตวแพทย์เห็นตัวเลขแจ้งเตือนบนแท็บ และเลือก **รับเข้าระบบ** หรือ **ตีกลับ** ได้
- ปุ่ม **✉️ ร่างอีเมลตอบรับผู้ยื่น** เปิด Outlook พร้อมข้อความสำเร็จรูป — ส่งจาก @psu.ac.th ของสัตวแพทย์เอง

### การส่งอีเมลอัตโนมัติ (ทางเลือก)

`request.html` มีค่าคงที่ `WEBHOOK_URL` ที่ปล่อยว่างไว้ เมื่อใส่ URL ของ n8n webhook แล้ว
ระบบจะยิงข้อมูลคำขอไปให้ n8n ส่งอีเมลแจ้งสัตวแพทย์และตอบรับนักวิจัยอัตโนมัติ

- ไฟล์ workflow พร้อมนำเข้า: [`n8n-workflow.json`](n8n-workflow.json)
- คู่มือติดตั้งทีละขั้น: [`n8n-setup.md`](n8n-setup.md)

การยิง webhook เป็นแบบ *ส่งแล้วไม่รอผล* — ถ้า n8n ล่ม คำขอยังบันทึกลง Firebase และเข้ากล่อง
“คำขอเข้าใหม่” ตามปกติ **ระบบไม่ขึ้นกับ n8n**

## ข้อสังเกตเกี่ยวกับ SOP

**เกณฑ์ที่ระบบใช้จริง = 14 วัน**

เนื้อความ **ข้อ 6.1** ระบุให้ยื่นคำขอก่อนวันเริ่มใช้ยาอย่างน้อย **30 วัน**
แต่ผังขั้นตอน **ข้อ 7** ในเอกสารฉบับเดียวกันระบุ **14 วัน**

หน่วยงานพิจารณาแล้วให้ใช้ **14 วัน ตามผังขั้นตอน** และระบบตั้งค่าตามนี้ (แก้ได้ที่หน้า “ตั้งค่าระบบ”)

> ควรแก้เนื้อความข้อ 6.1 ให้เป็น **14 วัน** ในการทบทวน SOP ฉบับถัดไป เพื่อให้เอกสารตรงกับการปฏิบัติจริง
